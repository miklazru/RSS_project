# RSS News Filter

Командное ДЗ №2 по курсу генеративных моделей / анализа текста (ФТиАД, ВШЭ).

Веб-приложение собирает новости из RSS/Atom-лент и показывает каждому пользователю только те, что прошли его фильтры: по ключевым словам и по темам (семантический поиск). У каждой новости видно, **почему** она в ленте. Есть свой тестовый RSS-канал, в который можно публиковать посты.

> **Статус:** готовы ядро (роль 1), сборщик и тестовый канал (роль 2), поиск по ключевым словам (роль 3), семантический поиск (роль 4) и веб-интерфейс (роль 5) на `/`. API и Swagger — на `/docs`.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt

python -m scripts.seed             # демо-данные: 20 статей и пользователи Аня и Боря
uvicorn app.main:app --reload      # интерфейс: http://localhost:8000, API: /docs
```

Через Docker (данные хранятся в томе и переживают перезапуск):

```bash
docker build -t rss-news-filter .
docker run -d -p 8000:8000 -v rss-data:/app/data --name rss-news-filter rss-news-filter
```

Если Docker Hub не отвечает, базовый образ можно взять из зеркала:
`docker pull mirror.gcr.io/library/python:3.12-slim && docker tag mirror.gcr.io/library/python:3.12-slim python:3.12-slim`.

## Как устроено

```
RSS/Atom-каналы ──► fetcher (раз в N сек) ──► pipeline.ingest ──► Article
                                                     │
                       Filter пользователей ──► matching (keyword / topic) ──► Match + причины
                                                     │
                                       GET /api/users/{id}/feed ──► лента с «почему здесь»

Свой канал: POST /api/own-channel/posts ──► TestPost ──► сразу в ingest (без ожидания обхода)
                                                    └──► GET /rss/test.xml для внешних читалок
```

### Контракт движков (`app/matching/base.py`)

Движок — это класс с полем `kind` и методом `match()`. Он не знает про БД, HTTP и UI, поэтому его можно писать и тестировать отдельно.

```python
class KeywordMatcher:
    kind = "keyword"

    def match(self, article: ArticleData, flt: FilterData) -> MatchResult:
        ...
        return MatchResult(
            matched=True,
            score=1.0,
            reasons=["слово «санкции» в заголовке (форма «санкциями»)"],
        )
```

- `ArticleData`: `id`, `title`, `summary`, `link`, `published_at`, `text` (заголовок + описание).
- `FilterData`: `id`, `kind` (`"keyword"` / `"topic"`), `query`, `threshold`.
- `MatchResult`: `matched`, `score` (для тем — сходство), `reasons` — **человекочитаемые** причины, их видит пользователь.

Чтобы заменить заглушку семантического движка, достаточно переписать свой файл, сохранив имя класса. Тесты `tests/test_matching_contract.py` проверяют контракт.

### Поиск по ключевым словам

- Русские словоформы приводятся к лемме через `pymorphy3`. Регистр и различие между «ё» и «е» при поиске игнорируются.
- Фраза ищется среди соседних слов в пределах предложения. Порядок слов может отличаться, повторяющееся слово учитывается столько раз, сколько оно встречается в запросе.
- На слово или фразу допускается одна вставка, потеря, замена или перестановка соседних букв. Одна из сравниваемых форм должна содержать не менее четырёх букв. Для русского слова опечатка проверяется, если хотя бы одна форма отсутствует в словаре. Для английских слов сравнивается написание.
- Для каждого поля движок предпочитает точное совпадение или совпадение по леммам совпадению с опечаткой. Причина содержит запрос, исходный фрагмент и место. Например, `фраза «новые санкции» в тексте: «санкциями, новыми»`.

Если база была заполнена до обновления движка, пересчитайте сохранённые совпадения командой `python -m scripts.rebuild_keyword_matches` с тем же `DB_PATH`, что и у приложения.

### Принятые решения

- **Фильтры объединяются через ИЛИ:** статья в ленте, если сработал хотя бы один фильтр. У статьи показываются **все** сработавшие фильтры.
- **Каналы общие** для всех пользователей (одна лента не скачивается дважды), а подписки у каждого свои. Лента пользователя строится только из его каналов.
- **Новый фильтр и новая подписка сразу применяются** к уже скачанным статьям, ждать следующего обхода не нужно.
- **Новый пользователь автоматически подписан на наш тестовый канал**, чтобы на демо пост сразу было видно.
- **Новый канал скачивается сразу** после добавления (в фоне), дальше — по расписанию.
- **Сломанный канал не мешает остальным:** ошибка записывается в `last_error` и видна в `GET /api/channels`.
- **SQLite и параллельная работа:** транзакции короткие и берут блокировку на запись сразу (`BEGIN IMMEDIATE`), а скачивание по сети идёт вне транзакций. Иначе фоновый сборщик и запросы пользователей ловят `database is locked` (есть тест `tests/test_concurrency.py`).
- **Даты в API всегда в UTC** с явным поясом.

## API (главное)

| Метод | Путь | Что делает |
|---|---|---|
| `GET`, `POST` | `/api/users` | список / создать пользователя |
| `DELETE` | `/api/users/{id}` | удалить пользователя со всеми фильтрами |
| `GET`, `POST` | `/api/users/{id}/filters` | фильтры пользователя / добавить (`kind`, `query`, `threshold`) |
| `PATCH` | `/api/users/{id}/filters/{filter_id}` | изменить порог темы (`{"threshold": 0.3}`, `null` — по умолчанию); совпадения пересчитываются сразу |
| `DELETE` | `/api/users/{id}/filters/{filter_id}` | удалить фильтр |
| `GET` | `/api/users/{id}/channels` | каналы пользователя |
| `POST` | `/api/users/{id}/channels` | добавить канал по ссылке и подписаться (одним действием) |
| `PUT`, `DELETE` | `/api/users/{id}/channels/{channel_id}` | подписаться / отписаться |
| `GET` | `/api/users/{id}/feed?limit=50` | отфильтрованная лента с причинами |
| `GET`, `POST` | `/api/channels` | все каналы (с `last_error`) / добавить |
| `POST` | `/api/channels/{id}/refresh` | скачать канал прямо сейчас |
| `GET`, `POST` | `/api/own-channel/posts` | посты нашего канала / опубликовать |
| `GET` | `/rss/test.xml` | наш канал в формате RSS 2.0 |
| `GET` | `/rss/test/{id}` | страница поста нашего канала (на неё ведут ссылки из ленты и RSS) |

Пример элемента ленты:

```json
{
  "title": "Новые санкции против банковского сектора",
  "channel_title": "Тестовый канал",
  "matches": [
    {"kind": "keyword", "query": "санкции", "score": 1.0,
     "reasons": ["слово «санкции» в заголовке: «санкции»"]}
  ]
}
```

- `test_acceptance.py` — сценарий приёмки препода по шагам: пост под фильтр появляется, пост не под фильтр не появляется, новый фильтр, два пользователя с разными лентами, перезапуск сервиса.

- `test_matching_contract.py` — контракт движков (должен проходить и после замены заглушек).

- `test_filter_threshold.py` — изменение порога темы: пересчёт совпадений, сброс к порогу по умолчанию, ошибки.

### Интерфейс

Обычные HTML + CSS + JavaScript (`fetch`) в `app/static/`, FastAPI отдаёт их сам: `/` — страница, `/static/...` — файлы. Ни Node, ни сборки, ни CDN — работает на демо-ноутбуке без интернета. Тест `test_ui.py` следит, чтобы внешние ссылки не появились.

- **Пользователь** выбирается в шапке (запоминается в браузере), там же «+ Новый» и «Удалить». Новый пользователь сразу подписан на тестовый канал.
- **Лента** опрашивает `/api/users/{id}/feed` каждые 5 секунд, пока вкладка браузера открыта (автообновление можно выключить). Новые статьи помечаются «новое». У каждой статьи блок «Почему в ленте»: все сработавшие фильтры с причинами движков, для тем — шкала сходства. Найденные по ключевым словам фрагменты подсвечиваются в заголовке и тексте. Чипсы над лентой оставляют статьи одного фильтра.
- **Фильтры:** ключевые слова или тема; для темы можно задать свой порог (иначе — порог по умолчанию). Пока тема считается моделью, кнопка показывает «Считаю…». У каждого фильтра видно, сколько статей он пропустил. Порог уже созданной темы регулируется ползунком прямо в списке: отпустили — совпадения пересчитаны, лента обновилась; «по умолчанию» возвращает общий порог.
- **Каналы:** добавить по ссылке и подписаться одним действием, подписаться на уже известный канал, отписаться, скачать сейчас. У каждого канала статус: когда скачан или текст `last_error`.
- **Наш канал:** публикация поста и список постов. После публикации интерфейс сообщает, попал ли пост в ленту текущего пользователя.

Сценарий для демо (после `python -m scripts.seed`): выбрать Аню → «Наш канал» → опубликовать пост «Новые санкции против металлургов» → «Лента»: пост уже там с пометкой «новое» и причиной «слово «санкции» в заголовке». Переключиться на Борю — у него этого поста нет (его фильтры про спорт и ИИ).

### Семантический поиск

Используется Python 3.12.

Для Linux без GPU сначала установите CPU-сборку Torch:

```bash
python -m pip install torch==2.15.0+cpu --index-url https://download.pytorch.org/whl/cpu
```

Для macOS:

```bash
python -m pip install torch==2.15.0
```

Затем установите зависимости:

```bash
python -m pip install -r requirements-dev.txt
```

Для запуска приложения с семантическим поиском скачайте модель:

```bash
python -m scripts.download_minilm
```

Для обычного запуска pytest скачивание модели не требуется.

Перед сборкой Docker модель также должна быть скачана:

```bash
docker build -t rss-project:topics .
```

Подробности и ограничения — в topics.md.
