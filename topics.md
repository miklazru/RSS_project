# Семантический поиск

Модуль `app/matching/semantic.py` определяет, подходит ли новость
под тему пользователя. Используется готовая мультиязычная модель
`paraphrase-multilingual-MiniLM-L12-v2`, работающая на CPU.

Модель сравнивает тему с заголовком и описанием статьи.
Если сходство не ниже порога фильтра, статья попадает в ленту.
В объяснении показываются тема, сходство и порог.

## Как запустить

Нужен Python 3.12. Установите зависимости по инструкции в README,
затем скачайте модель:

```bash
python -m scripts.download_minilm
```

Веса сохраняются в `models/multilingual-minilm` и не входят в Git.
При работе приложение загружает модель только с диска.
Другой путь можно задать через `TOPIC_MODEL_PATH`.

Запуск без обращений модели к HuggingFace:

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 uvicorn app.main:app --reload
```

## Загрузка и кэш

- `preload()` загружает модель при старте приложения.
- `warm_up()` вычисляет эмбеддинги статей пачками по 64.
- Кэш использует текст статьи, поэтому работает и до записи в БД,
  когда у статей ещё нет уникальных ID.
- Повторяющиеся тексты не вычисляются заново. Темы тоже кэшируются.
- Начальная ёмкость кэша статей — 2000 записей. Она увеличивается
  до размера крупнейшего набора прогрева.
- После перезапуска кэш заполняется заново.

## Проверки

```bash
python -m pytest -q
```

Проходят 109 тестов. Для общих тестов скачивать модель не нужно:
используется подмена. Качество поиска проверяется отдельно:

```bash
python -m scripts.evaluate_minilm
```

Замер скорости движка на 200 статьях:

```bash
python -m scripts.benchmark_topics
```

На моём компьютере прогрев и сопоставление заняли около
1 секунды, повторный проход из кэша — 0,001 секунды.
Загрузка модели в этом запуске отдельно заняла 22,7 секунды.

Проверка полного запроса создания фильтра через API:

```bash
python -m scripts.benchmark_topics_api
```

Скрипт использует настоящую модель и отдельную временную базу
с 200 статьями. Рабочая база не затрагивается.

Результаты после добавления пакетного прогрева:
- запуск приложения — 3,055 секунды;
- первое создание фильтра — 1,043 секунды;
- создание второго фильтра с той же темой — 0,017 секунды;
- первый запрос кодирует 200 статей пачкой и отдельно тему;
- второй запрос не вызывает модель;
- в ленте получены 5 статей с объяснениями совпадений.

Это результаты отдельных запусков на моём компьютере.
Время загрузки и обработки может отличаться в другом окружении.

Ранее вручную через API проверены русская и английская статьи
по русской теме, отсев постороннего поста и обработка новой статьи
после перезапуска. Эта ручная проверка проводилась до добавления
пакетного прогрева.

## Docker

Перед сборкой модель должна быть скачана:

```bash
python -m scripts.download_minilm
docker build -t rss-project:topics .
```

В образ включены модель и CPU-сборка Torch 2.15.0+cpu.
Сборка проверена на ARM64.

В контейнере с полностью отключённой сетью (`--network none`)
движок нашёл русскую и английскую статьи про космос
и отсеял пост про пекарню.

## Пороги и ограничения

Порог задаётся отдельно для каждого фильтра, по умолчанию — 0.5.
Это оценка сходства, а не вероятность правильного ответа.

Модель учитывает первые 128 токенов заголовка и описания.
Короткие или неоднозначные тексты могут определяться неверно.
Порог стоит проверять на примерах конкретной темы.

Потребление памяти кэшем зависит от крупнейшего набора прогрева.
При вытеснении статьи её эмбеддинг вычисляется заново.
Эмбеддинг новой темы вычисляется при первом `match()`.

После смены модели старые совпадения в БД автоматически
не пересчитываются.
